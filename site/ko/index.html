MemorY

Memory의 M부터 Y까지모든 것을 책임지는 솔루션

서버의 메모리 오류 기록을 읽어, DIMM 어디에 어떤 모양의 고장이 있는지 그림으로 보여주는 읽기 전용 오픈소스 도구입니다.

GitHub agenticode/my 빠른 시작 개발 중

소개

기록을 읽기만 합니다

MemorY는 Linux 서버가 이미 남긴 메모리 오류 기록을 읽습니다. 페이지 offline, 리페어, 카운터 초기화 같은 조치는 하지 않습니다.

읽은 기록은 DIMM 시리얼 번호를 기준으로 원장 하나에 모읍니다. 재부팅해도 이력이 남고, DIMM을 다른 슬롯으로 옮겨도 이력이 따라갑니다.

입력 rasdaemon DB kernel log EDAC sysfs SMBIOS BMC SEL Redfish nvidia-smi CXL mcelog FMFM JSON

문제

메모리 오류 로그는 아직 사람이 손으로 읽습니다

  1. 로그 형식이 출처마다 다릅니다.
  2. 주소는 디바이스, 뱅크, row, column으로 직접 풀어야 합니다.
  3. 카운터는 재부팅하면 처음부터 다시 셉니다.
  4. DIMM 문제인지 슬롯 문제인지는 짐작으로 정합니다.
  5. 보고서에 넣을 그림은 손으로 그립니다.

그림

그림으로 보여줍니다

그림마다 답하는 질문이 하나씩 있습니다. 아래 화면은 저장소의 testdata/real에 있는 랩 캡처를 MemorY로 읽은 출력입니다. tools/captures.mjs가 터미널에서 명령을 돌려 그대로 찍고, 그림에 따라 줄 단위로만 잘랐습니다.

앞의 세 그림은 DIMM 6개를 단 aarch64 게스트입니다. 하루 간격으로 세 번 부팅하면서 펌웨어 오류 레코드로 CE 35건과 UE 1건을 넣었습니다. DIMM 4개에 셀 하나, row, column, bank 고장을 하나씩 넣었고 2개는 비워 두었습니다. 그다음 두 그림은 치명적 오류로 부팅이 거듭 멈춘 게스트 둘입니다.

검증

실제 커널이 남긴 기록으로 시험합니다

랩 서버의 Fedora VM(커널 7.3.0)과 그 안의 QEMU 게스트에 위치를 아는 메모리 오류를 넣고, 커널과 rasdaemon이 남긴 기록을 그대로 떠 왔습니다. 캡처는 17개입니다. 커널은 7.3.0과 6.19.10, rasdaemon은 0.8.0과 1.0.0입니다. x86_64 게스트의 머신 체크, CXL 메모리 장치의 오류, 페이지 offline, aarch64 게스트의 펌웨어 오류 레코드, 치명적 오류로 멈춘 부팅을 담았습니다.

위 그림은 이 가운데 캡처 셋을 읽었습니다.

6.19.10-ghes-multi
aarch64 게스트에 DIMM 6개를 달고 하루 간격으로 세 번 부팅했습니다. DIMM 4개에 펌웨어 오류 레코드 36건(CE 35건, UE 1건)을 넣었습니다.
6.19.10-bert-loop
x86 게스트를 세 번 부팅했습니다. QEMU가 리셋할 때마다 손으로 만든 BERT 영역을 써 넣어서, 게스트는 부팅마다 앞 부팅이 DIMM 0의 같은 셀(row 0x1a2f, column 0x238)에서 난 치명적 오류로 끝났다는 기록을 읽습니다. 게스트는 재부팅 명령으로 다시 시작했습니다.
6.19.10-ghes-loop-spread
DIMM 6개를 단 aarch64 게스트에서 부팅 세 번 동안 부팅마다 다른 DIMM(CPU0_A1, CPU0_C1, CPU0_E1)에 치명적 펌웨어 오류 레코드를 1건씩 넣었습니다. 커널은 그때마다 패닉으로 멈췄습니다.

캡처를 읽으면서 고친 결함은 18가지이고, validation-lab.md에 하나씩 적었습니다. 두 가지 예입니다.

  1. dmidecode 3.7은 용량을 16 GiB로 적습니다. 이 표기를 읽지 못해 꽂힌 DIMM을 하나도 찾지 못했습니다.
  2. aarch64 게스트의 패닉 한 번은 EFI 변수에 조각 16개로 남았습니다. 조각이 3초에 걸쳐 쓰여 systemd-pstore가 디렉터리 셋에 나눠 담았고, MemorY는 이를 덤프 셋으로 읽어 패닉 한 번을 부팅 셋으로 셌습니다. 부팅 5회가 15회로 보였습니다. 지금은 Part 1부터 이어지는 조각을 덤프 하나로 읽습니다.

랩에는 실제 메모리 컨트롤러, EINJ, BMC, GPU가 없습니다. 실행 중인 Linux 호스트 5대에서 돌린 결과는 validation.md에 있습니다. 다섯 호스트 모두 가상 머신이라 EDAC 메모리 컨트롤러가 없습니다.

시작

빠른 시작 개발 중

바이너리 하나, 명령 하나입니다.

$ my

릴리스는 아직 없습니다. 지금은 소스에서 빌드합니다. Go 1.26 이상이 필요합니다.

$ git clone https://github.com/agenticode/my
$ cd my
$ make build    # bin/my

서버가 없어도 저장소의 랩 캡처로 돌려 볼 수 있습니다. --root에 캡처 디렉터리를 주면 그 호스트의 파일을 읽습니다. 로케일이 한국어면 한국어로 출력합니다.
