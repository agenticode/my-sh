MemorY

Memory의 M부터 Y까지모든 것을 책임지는 솔루션

서버에 남은 메모리 오류 기록을 읽고, 고장이 DIMM 어디에서 어떤 모양으로 났는지 그림으로 보여 줍니다.읽기 전용 오픈소스 도구입니다.

GitHub agenticode/my 빠른 시작 다운로드

소개

기록을 읽기만 합니다

MemorY는 Linux 서버에 이미 남아 있는 메모리 오류 기록을 읽습니다.페이지 offline, 리페어, 카운터 초기화는 하지 않습니다.

읽은 기록은 DIMM 시리얼 번호별로 원장 하나에 모읍니다.재부팅한 뒤에도 이력이 남습니다.DIMM을 다른 슬롯으로 옮기면 이력도 같이 옮겨 갑니다.

입력 rasdaemon DB kernel log EDAC sysfs SMBIOS BMC SEL Redfish nvidia-smi CXL mcelog FMFM JSON

문제

메모리 오류 로그는 아직 사람이 직접 읽습니다

  1. 로그 형식이 소스마다 다릅니다.
  2. 물리 주소를 device, bank, row, column으로 직접 디코딩해야 합니다.
  3. EDAC 카운터는 재부팅하면 처음부터 다시 셉니다.
  4. DIMM 문제인지 슬롯 문제인지는 짐작으로 판단합니다.
  5. 보고서에 넣을 그림은 직접 그립니다.

그림

그림으로 보여 줍니다

아래 화면은 모두 MemorY를 실제로 실행한 출력입니다.입력은 저장소 testdata/real에 있는 랩 캡처입니다.tools/captures.mjs가 터미널에서 명령을 실행하고 화면을 그대로 찍었습니다.그림에 따라 출력 일부를 줄 단위로 잘랐습니다.

처음 세 그림의 입력은 DIMM 6개짜리 aarch64 게스트입니다.하루 간격으로 세 번 부팅하며 펌웨어 오류 레코드로 CE 35건, UE 1건을 주입했습니다.DIMM 4개에는 셀, row, column, bank 고장을 하나씩 넣었습니다.나머지 DIMM 2개에는 오류가 없습니다.다음 두 그림은 치명적 오류로 부팅이 계속 멈춘 게스트 두 대의 기록입니다.

검증

실제 커널이 남긴 기록으로 테스트합니다

랩 서버의 Fedora VM(커널 7.3.0)과 그 안의 QEMU 게스트에 위치를 정해 메모리 오류를 주입했습니다.커널과 rasdaemon이 남긴 기록은 그대로 캡처했습니다.

캡처
17개
커널
7.3.0, 6.19.10
rasdaemon
0.8.0, 1.0.0
담긴 기록
x86_64 게스트의 머신 체크, CXL 메모리 장치 오류, 페이지 offline, aarch64 게스트의 펌웨어 오류 레코드, 치명적 오류로 멈춘 부팅

위 그림에 쓴 캡처는 아래 3개입니다.

6.19.10-ghes-multi
DIMM 6개짜리 aarch64 게스트를 하루 간격으로 세 번 부팅했습니다.DIMM 4개에 펌웨어 오류 레코드 36건(CE 35건, UE 1건)을 주입했습니다.
6.19.10-bert-loop
x86 게스트를 세 번 부팅했습니다.미리 만들어 둔 BERT 영역을 QEMU가 리셋할 때마다 다시 써 넣었습니다.게스트는 부팅할 때마다, 직전 부팅이 DIMM 0의 같은 셀(row 0x1a2f, column 0x238)에서 난 치명적 오류로 끝났다는 기록을 읽습니다.세 부팅 모두 실제로는 재부팅 명령으로 끝났습니다.
6.19.10-ghes-loop-spread
DIMM 6개짜리 aarch64 게스트를 세 번 부팅하며, 부팅마다 다른 DIMM(CPU0_A1, CPU0_C1, CPU0_E1)에 치명적 펌웨어 오류 레코드를 1건씩 주입했습니다.커널은 매번 패닉으로 멈췄습니다.

캡처를 읽으며 결함 18개를 고쳤습니다.전체 목록: validation-lab.md그중 두 가지:

  1. dmidecode 3.7은 DIMM 용량을 16 GiB로 출력합니다.MemorY가 이 표기를 읽지 못해서 꽂힌 DIMM을 하나도 찾지 못했습니다.
  2. aarch64 게스트에서 패닉 한 번의 기록이 EFI 변수에 조각 16개로 저장됐습니다.조각이 3초에 걸쳐 쓰여서 systemd-pstore가 디렉터리 3개에 나눠 담았습니다.MemorY는 이를 덤프 3개로 읽고 패닉 한 번을 부팅 3번으로 셌습니다.부팅 5번이 15번으로 잡혔습니다.지금은 Part 1부터 이어지는 조각을 덤프 하나로 읽습니다.

랩에는 실제 메모리 컨트롤러, EINJ, BMC, GPU가 없습니다.가동 중인 Linux 호스트 5대의 결과: validation.md5대 모두 가상 머신이라 EDAC 메모리 컨트롤러가 없습니다.

시작

빠른 시작

MemorY는 바이너리 하나입니다.Linux와 macOS 터미널에서 한 줄로 설치합니다.

$ curl -fsSL https://my.sh/get | sh

스크립트 내용, 파일별 체크섬, 소스 빌드: 다운로드

서버에서는 인자 없이 실행합니다.

$ my

서버가 없으면 저장소에 든 랩 캡처로 돌려 봅니다.--root에 캡처 디렉터리를 주면 그 호스트의 파일을 읽습니다.로케일이 한국어면 출력도 한국어입니다.

$ git clone --depth 1 https://github.com/agenticode/my
$ cd my
