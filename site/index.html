MemorY

Memory의 M부터 Y까지모든 것을 책임지는 솔루션

서버의 메모리 오류 기록을 읽어, DIMM 어디에 어떤 모양의 고장이 있는지 그림으로 보여주는 읽기 전용 오픈소스 도구입니다.

GitHub agenticode/my 빠른 시작 개발 중

소개

기록을 읽기만 합니다

MemorY는 Linux 서버가 이미 남긴 메모리 오류 기록을 읽습니다. 페이지 offline, 리페어, 카운터 초기화 같은 조치는 하지 않습니다.

읽은 기록은 DIMM 시리얼 번호를 기준으로 원장 하나에 모읍니다. 재부팅해도 이력이 남고, DIMM을 다른 슬롯으로 옮겨도 이력이 따라갑니다.

입력 rasdaemon DB kernel log EDAC sysfs SMBIOS BMC SEL Redfish nvidia-smi CXL mcelog FMFM JSON

문제

메모리 오류 로그는 아직 사람이 손으로 읽습니다

  1. 로그 형식이 출처마다 다릅니다.
  2. 주소는 디바이스, 뱅크, row, column으로 직접 풀어야 합니다.
  3. 카운터는 재부팅하면 처음부터 다시 셉니다.
  4. DIMM 문제인지 슬롯 문제인지는 짐작으로 정합니다.
  5. 보고서에 넣을 그림은 손으로 그립니다.

그림

그림으로 보여줍니다

그림마다 답하는 질문이 하나씩 있습니다. 아래 화면은 랩의 aarch64 게스트에 펌웨어 오류 레코드로 CE 24건, UE 2건을 넣고 MemorY로 읽은 결과입니다. 타임라인은 같은 게스트의 다음 부팅까지 한 케이스로 묶었습니다.

검증

실제 커널이 남긴 기록으로 시험합니다

랩 서버의 Fedora VM(커널 7.3.0)과 그 안의 QEMU 게스트에 위치를 아는 메모리 오류를 넣고, 커널과 rasdaemon이 남긴 기록을 그대로 떠 왔습니다. 캡처는 11개입니다. x86_64 게스트의 머신 체크, CXL 메모리 장치의 오류, 페이지 offline, aarch64 게스트의 펌웨어 오류 레코드를 담았고, 커널은 7.3.0과 6.19.10, rasdaemon은 0.8.0과 1.0.0입니다.

캡처는 저장소의 testdata/real/에 있습니다. 테스트가 매번 넣은 오류와 MemorY가 센 오류를 대조하고, my verify로 직접 대조할 수도 있습니다.

캡처를 읽으면서 찾은 결함을 PR 11건으로 고쳤습니다. 두 가지 예입니다.

  1. dmidecode 3.7은 용량을 16 GiB로 적습니다. 이 표기를 읽지 못해 꽂힌 DIMM을 하나도 찾지 못했습니다.
  2. rasdaemon이 뜬 뒤 시계가 10초 뒤로 돌아간 부팅에서, rasdaemon의 시각이 커널 시각보다 10초 앞섰습니다. 같은 오류를 두 번 세어, 넣은 CE 10건과 UE 1건을 CE 18건과 UE 2건으로 표시했습니다. 지금은 같은 부팅의 커널 로그 시각에 맞춰 한 번만 셉니다.

랩 VM 자체에서도 돌렸습니다. VMware 가상 보드라 메모리 컨트롤러의 EDAC 드라이버가 없고, MemorY는 없는 소스를 빼고 읽은 소스만으로 그립니다.

$ my scan --width 52
 슬롯 128개, DIMM 3개

 오류 기록이 있는 DIMM 없음

 오류 없는 DIMM 3개
 이 호스트의 page offline 80건은 어느 DIMM에도 묶이지 않음
 소스  hostinfo 2건, rasdaemon 6건, klog (저널) 160건, klog
       (링 버퍼) 7건, edac-sysfs 기록 없음, smbios 128건

랩에는 실제 메모리 컨트롤러, EINJ, BMC, GPU가 없습니다. 실서버 기록으로 하는 검증과 공개 현장 데이터 평가가 다음 단계입니다.

시작

빠른 시작 개발 중

바이너리 하나, 명령 하나입니다.

$ my

릴리스는 아직 없습니다. 지금은 소스에서 빌드합니다. Go 1.26 이상이 필요합니다.

$ git clone https://github.com/agenticode/my
$ cd my
$ make build    # bin/my

자주 쓰는 명령입니다.

$ my                          # 이 호스트의 슬롯 맵과 DIMM 순위
$ my why "DIMM 0"             # 판정과 근거
$ my bundle -o case.mycase    # 기록을 케이스 파일 하나로
$ my open case.mycase         # 받은 케이스를 같은 화면으로
$ my report case.mycase -o report.html

그림 화면, HTML 리포트, 케이스 번들, Prometheus exporter, my diff, my verify, 분석기 플러그인 계약은 main에 들어갔습니다. BMC에 Redfish로 직접 묻는 수집과 공개 현장 데이터 평가는 작업 중입니다. 진행 상황은 GitHub 저장소에 있습니다.
